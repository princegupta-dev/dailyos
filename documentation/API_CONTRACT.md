# DailyOS habit tracker: future API contract

> **Status: design only.** DailyOS has no backend. All data lives in IndexedDB on the device,
> and the app works fully offline. This document describes the HTTP API a future sync server
> would expose, so that the local data model and the server stay compatible. Nothing here is
> implemented or called by the app today.

Each endpoint is mapped to the local repository function that does the same job today
(`src/db/repositories/habits.ts`). The request and response bodies use the same field names and
validation rules as the Zod schemas in `src/domain/habit.ts`, so a server can reuse them.

## Conventions

| Topic           | Rule                                                                                                                                                                                         |
| --------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Base URL        | `/v1`. Breaking changes get a new version prefix.                                                                                                                                            |
| Format          | JSON, UTF-8. Absent optional fields are omitted, never `null` (except where a body says so).                                                                                                 |
| Auth            | `Authorization: Bearer <token>`. Every resource belongs to one user; other users' resources return `404`.                                                                                    |
| IDs             | UUID v4 strings, generated by the **client**. Records can then be created offline and synced later without remapping.                                                                        |
| Dates           | A habit day is a local date key `YYYY-MM-DD`, not a timestamp. The user's IANA time zone (in settings) decides which day "today" is. The server never converts date keys between time zones. |
| Timestamps      | ISO 8601 UTC (`createdAt`, `updatedAt`, `archivedAt`).                                                                                                                                       |
| Concurrency     | Every record has `updatedAt`. Writes may send `If-Unmodified-Since-Version: <updatedAt>`; the server returns `409 conflict` if the record changed in the meantime.                           |
| Idempotency     | `PUT` and `DELETE` are idempotent. `POST` accepts an `Idempotency-Key` header so retries after a dropped connection don't create duplicates.                                                 |
| No hard deletes | Habits are ended, never deleted, so history and reviews stay intact. Individual entries can be cleared (to correct a mistake).                                                               |

### Errors

Errors use the same `kind` values as the app's `AppError` (`src/db/errors.ts`):

```json
{
  "error": {
    "kind": "validation",
    "message": "Choose at least one day",
    "issues": [{ "path": "weekdays", "message": "Choose at least one day" }]
  }
}
```

| `kind`              | HTTP | When                                                                                       |
| ------------------- | ---- | ------------------------------------------------------------------------------------------ |
| `validation`        | 400  | The body fails the schema. `issues` lists each field.                                      |
| `not_found`         | 404  | No such habit, or it belongs to someone else.                                              |
| `invalid_operation` | 422  | Valid input that breaks a rule: a future date, an unscheduled day, editing an ended habit. |
| `conflict`          | 409  | Concurrent change, or a duplicate entry for the same habit and date.                       |
| `version`           | 426  | The client's schema version is too old to sync.                                            |
| `unavailable`       | 503  | Temporary server problem; retry with backoff.                                              |

## Data shapes

### Habit

```json
{
  "id": "6f1c…",
  "name": "Gym workout",
  "description": "Strength keeps my back healthy",
  "category": "fitness",
  "frequency": "selected_days",
  "weekdays": [1, 2, 3, 4, 5],
  "target": 45,
  "unit": "min",
  "minimumTarget": "15 minute walk",
  "alternatives": ["Running", "Swimming"],
  "startDate": "2026-10-01",
  "position": 0,
  "createdAt": "2026-10-01T08:12:00.000Z",
  "updatedAt": "2026-10-01T08:12:00.000Z",
  "archivedAt": "2026-12-01T09:00:00.000Z",
  "archivedOn": "2026-12-01"
}
```

| Field           | Rules                                                                                                                                                     |
| --------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`          | Required, 1–80 characters.                                                                                                                                |
| `description`   | Optional, up to 500. Shown as "Why it matters".                                                                                                           |
| `category`      | `engineering` · `dsa` · `fitness` · `reading` · `career` · `attention` · `other`. Defaults to `other`.                                                    |
| `frequency`     | `daily` · `selected_days` · `weekly` (once, on any day of the week).                                                                                      |
| `weekdays`      | Required and non-empty for `selected_days`, otherwise omitted. `0` = Sunday … `6` = Saturday. "Weekdays" in the UI is `selected_days` with `[1,2,3,4,5]`. |
| `target`/`unit` | Optional positive number per occurrence, up to 100,000. `unit` (up to 20) only when there is a target.                                                    |
| `minimumTarget` | Optional, up to 120. The smallest version that still counts on a hard day.                                                                                |
| `alternatives`  | Optional, up to 8 unique items of up to 60 characters. Other activities that also count.                                                                  |
| `startDate`     | Set by the server to the user's local today on creation. Read-only.                                                                                       |
| `position`      | Display order. Read-only, except through the reorder endpoint.                                                                                            |
| `archivedOn`    | Set when the habit is ended. The habit doesn't count from this date on.                                                                                   |

### Habit entry (one check-in)

At most one entry per habit per date (unique on `habitId` + `date`).

```json
{
  "id": "a93e…",
  "habitId": "6f1c…",
  "date": "2026-10-02",
  "status": "completed",
  "note": "Felt strong today",
  "amount": 50,
  "minimum": false,
  "alternative": "Running",
  "log": { "workout": "Push day", "durationMin": 50, "details": "Bench 3x8" },
  "tags": ["Strength"],
  "createdAt": "2026-10-02T18:30:00.000Z",
  "updatedAt": "2026-10-02T18:30:00.000Z"
}
```

| Field         | Rules                                                                                                                                                                                                                                                                                                                   |
| ------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `status`      | `completed` · `skipped` · `missed`. There is no stored "pending": a day with no entry is pending today and missed afterwards.                                                                                                                                                                                           |
| `note`        | Optional, up to 500.                                                                                                                                                                                                                                                                                                    |
| `amount`      | Optional, 0–100,000, in the habit's unit.                                                                                                                                                                                                                                                                               |
| `minimum`     | Optional. Only kept when `status` is `completed`; still counts as a completion.                                                                                                                                                                                                                                         |
| `alternative` | Optional, up to 60.                                                                                                                                                                                                                                                                                                     |
| `log`         | Optional, category-specific details: keys up to 40 characters, values a string (up to 5,000) or a number (0–100,000). Empty strings are dropped. Keys aren't restricted to the current category, so changing a habit's category never invalidates old logs. Field keys per category are in `src/domain/activityLog.ts`. |
| `tags`        | Up to 20 unique tags of up to 40 characters. Always present (may be empty). Tags are only ever added by the user; suggestions are never applied automatically.                                                                                                                                                          |

### Derived values (never stored)

The server stores only habits and entries. Occurrences, streaks and rates are **computed**,
using the same rules as `src/domain/habit.ts`, so the client and server always agree:

- An **occurrence** is one chance to do a habit: each scheduled date, or each week for weekly
  habits. Unscheduled days aren't occurrences and never count against the user.
- Occurrence status is the entry's status. Without an entry, today's (or this week's)
  occurrence is `pending` and past ones are `missed`.
- **Streaks:** completed extends a run, skipped is neutral, missed ends it, and pending is
  ignored.
- **Rate** = completed ÷ (completed + missed). Skipped and pending don't count. When the
  denominator is 0 the rate is `null` ("not enough data"), never 0%.

```json
// HabitStats
{ "currentStreak": 3, "longestStreak": 12, "totalCompletions": 41 }

// OccurrenceSummary for a period
{ "completed": 18, "skipped": 2, "missed": 4, "pending": 1, "rate": 0.818 }
```

## Endpoints

### Habits

| Method & path              | Purpose                                                                                              | Local equivalent |
| -------------------------- | ---------------------------------------------------------------------------------------------------- | ---------------- |
| `GET /v1/habits`           | List habits in display order. `?status=active` (default) · `ended` · `all`.                          | `listHabits`     |
| `POST /v1/habits`          | Create a habit from a draft. Returns `201` with the habit.                                           | `createHabit`    |
| `GET /v1/habits/{id}`      | One habit with all its entries, oldest first: `{ habit, entries }`.                                  | `getHabitDetail` |
| `PUT /v1/habits/{id}`      | Replace the editable fields with a full draft. Optional fields left out are cleared. `422` if ended. | `updateHabit`    |
| `POST /v1/habits/{id}/end` | End the habit from the user's local today. Idempotent: ending an ended habit returns it unchanged.   | `endHabit`       |
| `PUT /v1/habits/order`     | Reorder: `{ "ids": ["…", "…"] }` sets `position` to each id's index. _Planned; no UI yet._           | —                |

There is deliberately no `DELETE /v1/habits/{id}`.

**Habit draft** (body of `POST` and `PUT`): `name` (required), `frequency` (required),
`description`, `category`, `weekdays`, `target`, `unit`, `minimumTarget`, `alternatives`.

```http
POST /v1/habits
Content-Type: application/json
Idempotency-Key: 0d1e…

{ "name": "Gym workout", "category": "fitness", "frequency": "selected_days",
  "weekdays": [1, 2, 3, 4, 5], "target": 45, "unit": "min",
  "minimumTarget": "15 minute walk", "alternatives": ["Running"] }
```

### Check-ins (entries)

| Method & path                              | Purpose                                                                                                    | Local equivalent                            |
| ------------------------------------------ | ---------------------------------------------------------------------------------------------------------- | ------------------------------------------- |
| `PUT /v1/habits/{id}/entries/{date}`       | Set the status for a date, creating or updating the entry. Used by the one-tap checkbox and the log sheet. | `setHabitStatus(id, date, status, details)` |
| `DELETE /v1/habits/{id}/entries/{date}`    | Clear the entry: undo an accidental check-off. Returns `204`, also when there was nothing to clear.        | `setHabitStatus(id, date, null)`            |
| `GET /v1/habits/{id}/entries?from=&to=`    | Entries for one habit in an inclusive date range.                                                          | `getHabitDetail`                            |
| `GET /v1/entries?from=&to=&tag=&category=` | Entries across all habits, for reviews and insights. Filters are optional.                                 | review and insight reads                    |

`PUT` body:

```json
{ "status": "completed", "details": { "amount": 50, "log": { "workout": "Push day" }, "tags": [] } }
```

- `details` is optional. **When it is left out, the details already recorded for that date are
  kept**, so changing only the status never loses a note or log. When it is sent, it replaces
  them.
- `422 invalid_operation` when `date` is after the user's local today, before the habit's
  `startDate`, on or after `archivedOn`, or not a scheduled day.
- Past dates are allowed, so the calendar can correct history (for example, missed → done).

### Views for the screens (derived, read-only)

These save the client from downloading every entry. Offline, the app computes the same
results locally, so each one is optional for a first server version.

| Method & path                                | Returns                                                                                                   | Used by                             | Local equivalent                     |
| -------------------------------------------- | --------------------------------------------------------------------------------------------------------- | ----------------------------------- | ------------------------------------ |
| `GET /v1/habits/summary?date=&includeEnded=` | Every habit with `stats`, `todayEntry` and `todayStatus` (`null` when it can't be checked off that day).  | Habits list                         | `listHabitSummaries`                 |
| `GET /v1/habits/day/{date}`                  | Only habits scheduled that day, with occurrence, entry and stats.                                         | Today                               | `getHabitsForDay`                    |
| `GET /v1/habits/{id}/stats?from=&to=`        | `HabitStats` plus an `OccurrenceSummary` for the period (week, month, 30 days or all).                    | Habit overview                      | `habitStats`, `summarizeOccurrences` |
| `GET /v1/habits/{id}/calendar?month=YYYY-MM` | One state per day: `completed` · `skipped` · `missed` · `pending` · `unscheduled` · `future`.             | Habit calendar                      | `habitOccurrences`                   |
| `GET /v1/insights/week?date=`                | `{ completed, counted, rate }` for the week so far, across active habits.                                 | Today progress card                 | `getWeekConsistency`                 |
| `GET /v1/insights/range?from=&to=`           | Per-habit and per-category summaries for a period. Values without enough data are `null`, never invented. | Insights, weekly and monthly review | `getRangeReport`                     |

### Settings

| Method & path      | Purpose                                                                                              |
| ------------------ | ---------------------------------------------------------------------------------------------------- |
| `GET /v1/settings` | `{ "timeZone": "Asia/Kolkata", "weekStartsOn": 1 }`. `weekStartsOn` is `0` (Sunday) or `1` (Monday). |
| `PUT /v1/settings` | Replace the settings. Changing the time zone never rewrites stored date keys.                        |

### Sync and backup

| Method & path                                     | Purpose                                                                                                                                                                                     |
| ------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `GET /v1/sync?since=<timestamp>`                  | Every record changed after `since`, including ended habits and cleared-entry tombstones (`{ "id", "deletedAt" }`), plus a new `cursor`.                                                     |
| `POST /v1/sync`                                   | Push local changes as a batch. Each record is accepted or returned with a `conflict` and the server's copy, so the client can merge.                                                        |
| `GET /v1/export`                                  | The same JSON backup file the app downloads from Settings: `{ "format": "dailyos-backup", "schemaVersion": 5, "exportedAt", "data": { … } }`.                                               |
| `POST /v1/import?mode=replace\|merge&dryRun=true` | Validate a backup and preview what would change; without `dryRun`, apply it. Invalid files are rejected as a whole. `merge` follows the app's "add what's new" rules (see ARCHITECTURE.md). |

## Not part of the API

- **Keyword and tag suggestions** are computed on the device from a local vocabulary and the
  user's own tags. No text is sent anywhere.
- **Streaks, rates and insights** are never stored on the server as the source of truth; they're
  always recomputed from habits and entries.
- Tasks, daily plans, learning notes and reviews will follow the same conventions in their own
  sections of this document when sync is built.
